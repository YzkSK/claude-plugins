# 読めて最短の実装

ponytail の「最小の変更」に従う。この skill はその中で形を選ぶ基準だけを足す。

**基準: 初めて読む人が前後を追わずに理解できる範囲で、最も短い形を選ぶ。** 読めないなら行数を増やす。読めるなら増やさない。

## 判定

| 迷い | 判定 |
|---|---|
| 既存コードと同じ処理が要る | 既存の関数をそのまま呼ぶ。将来の違いを推測して、新しい関数やラッパーを作らない |
| 既存の重複をまとめるか | 今の仕様で必ず一緒に変わるものだけ一つにする。単位やラベルだけ違うものは別々のままにする |
| 関数の切り出し | 名前が中身より短く正確に意味を伝えるときだけ切り出す |
| 名前 | 読む人が中身を見ずに正しく使えるようにする。書き換え・送信・例外などの副作用は名前に出す |
| コメント | コードから読めない理由・制約だけを書く。要件やコードの言い直しは書かない |
| 不正な状態 | 型や引数で作れなくできるなら、チェックを足さずそうする。`!` で黙らせない |
| 呼び出し順の依存 | 引数で渡せば消せるなら消す |

## 変更の範囲

- 要件に必要な箇所だけ直す。周辺の問題は直さず、報告する。
- 触った行が原因で古くなったコメントや名前は、同じ変更で直す。
- 同じ知識が新たに3か所目になるなら、書き足す前に一か所へまとめる。

## 書き終えたら

変更行を見直し、次のものを削る: 使われない引数、到達しない防御コード、コードの言い直しコメント、一度しか使わない抽象。
